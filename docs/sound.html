Sound

Bank 0 is the sound bank. Three of its nine entry slots are audio, and one of them runs every frame from the NMI handler.

Seven soft channels compete for four hardware ones. Per-channel state is a structure of arrays in page 3: field f of channel c lives at $0319 + 7f + c, so the stride is 7 and the channel index is the offset. $97E4 copies nine of those fields straight out of a song header; fields 7 and 8 are the track's stream pointer. Field 6 says which of the four hardware channels the voice wants, and $0306 is the busy mask over them — that is the whole allocator. Output goes to a 16-byte APU shadow at $0308-$0317, flushed by LDA $0308,X / STA $4000,X; a shadow byte of $FF means do not write that register this frame.

The stream format

ByteMeaning
$00-$7FA note. A duration byte may follow.
$80-$94One of 21 commands — the table below.
$95-$AFHole. Would index past the 21-entry dispatch table.
$B0-$DFHole. Would advance the stream pointer by zero — an infinite loop.
$E0-$FFRepeat the previous note with this duration. $E0 takes a literal byte; the rest index the duration table.
The holes are counted, not assumed. Walking all 132 tracks in the ROM byte by byte meets 810 command bytes, and 0 of them fall in either hole. Every one of those tracks reaches an unconditional terminator, 83 of them a jump back to a loop point, for 4,639 notes in total. A single wrong operand length would desynchronise a walk and send it off into the next track's bytes, so this is a check and not a restatement.

The DMC is a timer, not a voice

There is no sampled audio in this ROM. The DMC registers are written once, at bank 6 $802A: $4010 = $81 (IRQ enabled, rate 1), $4011 = $00, $4012 = $FF and $4013 = $01 — a 17-byte sample at $FFC0. Those 17 bytes are all zero, so the channel emits nothing. What it does instead is fire an IRQ: the handler at $DCF3 acknowledges it with $4015 = $0F, polls sprite 0 through BIT $2002 against the frame counter in $2B, and restarts the timer from $05 — nudging that rate index up and down between $81 and $89 to converge on the split. It is a self-calibrating mid-frame raster interrupt wearing the DMC's clothes.

Sound command dispatch pointer_table confirmed

bank0.tbl_932C · bank 0 $932C-$9355 · 42 bytes

21 entries, each a handler address minus one, indexed by ASL A at $9315 on a stream byte in $80-$94. Bounded by structure: entry 20 ends at $9355 and handler 0, the target of entry 0, begins at $9356. Registered in annotations/dispatch.json, which is what seeds the trace with all 21 arms.

Hardware channel masks data confirmed

bank0.snd_9771 · bank 0 $9771-$9778 · 8 bytes

Two four-byte tables: $9771 holds 01 02 04 08 and $9775 holds FE FD FB F7. $96CF indexes both by $0343,X - the hardware channel a soft channel wants - to test and then claim a bit in the busy mask $0306. Four bytes each because there are four hardware channels; this is the allocator that lets seven soft channels share them.

Note period table data confirmed

bank0.snd_985A · bank 0 $985A-$9931 · 216 bytes

108 little-endian 11-bit periods, $07FE down to $0004, read by $9596 as LDA $9840,Y / LDA $9841,Y with Y = (note + transpose) * 2. THE BASE IS $9840, NOT THIS ADDRESS: index 0 would land 26 entries earlier, in bytes that are not periods, so the used part of the table starts here at index $1A. The values are their own argument - a monotonically falling run of legal APU period values, halving about every twelve entries, which is an equal-tempered octave.

Note duration table data confirmed

bank0.snd_9942 · bank 0 $9942-$995F · 30 bytes

30 bytes, read by $94E6 as LDA $9941,Y with Y = duration byte - $E0. The first fifteen are 01 02 03 04 06 08 0C 10 18 20 30 40 60 80 C0 - a doubling series with dotted values between - and the rest are triplet and tied lengths. BOUNDED BY THE DATA, not by a guess: walking every track in the ROM and censusing the duration bytes gives exactly $E1-$FE, which is indices 1 to 30, which is exactly this many entries. Index 0 cannot occur because $E0 means 'the literal byte after me'.

Pitch envelope pointers pointer_table confirmed

bank0.tbl_9961 · bank 0 $9961-$9968 · 8 bytes

Four little-endian pointers, read by $964A as LDA $995F,Y / LDA $9960,Y with Y = ((index * 2) AND $7F) - the mask matters, and missing it makes the pointers come out as RAM addresses. They name $9969, $9972, $9994 and $99A1. The table ends where its own first target begins.

Pitch envelope data data confirmed

bank0.snd_9969 · bank 0 $9969-$99AC · 68 bytes

Four sequences of small signed bytes - 02 01 00 FF FE FF 00 01, and so on - each ending in a byte with bit 7 set ($81 or $82). These are per-frame pitch offsets: vibrato and slide shapes. WHAT THE TERMINATOR'S LOW BITS MEAN is not established; a loop point is the obvious guess and is not checked here.

Volume envelope pointers pointer_table confirmed

bank0.tbl_99AD · bank 0 $99AD-$99C4 · 24 bytes

Twelve little-endian pointers, read by $95B2 as LDA $99AB,Y / LDA $99AC,Y with Y = index * 2, so index 1 is the first entry. Bounded at both ends: index 0 is skipped by the BEQ two instructions earlier, and the twelfth entry ends at $99C4 with its own first target starting at $99C5. Censusing every $85 command in the ROM gives instrument numbers 1, 2, 3, 4, 9 and 10 - a subset of the twelve.

Volume envelope data data confirmed

bank0.snd_99C5 · bank 0 $99C5-$9ACC · 264 bytes

Twelve sequences of 4-bit volume levels, one per frame, named by the pointer table above. The first begins 0F 0F 0F 0F ... - a flat sustain. Extent runs to the first song header at $9ACD.

Song pointers (72 entries) pointer_table confirmed

bank0.tbl_9B04 · bank 0 $9B04-$9B93 · 144 bytes

72 little-endian pointers, read by $97E4 as LDA $9B04,X / LDA $9B05,X with X = song id * 2, after $97CC - bank 0's entry slot 2 - takes the id in A. BOUNDED BY STRUCTURE: the table ends at $9B93 and the lowest target above it is $9B94, the next byte, so it cannot be one entry longer. Five entries point at a byte of $00, which $97E4 treats not as a song but as code: it pushes the pointer and RTSes to it. The rest are song headers - a record count, then that many [channel][9 field] records, the last two fields being the track's stream pointer.
