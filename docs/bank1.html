Why this bank sits where it does

Opens with a 5-entry JMP table at $8000-$800E. Nothing else in this bank has been traced.

An address on this page does not identify a byte. $8000-$BFFF is the switchable window, so every address below exists in seven banks at once and only bank 1 has these particular bytes at it. Any address taken from a debugger, a wiki or another disassembly has to carry a bank with it before it means anything — tools/whereis.py --bytes settles which bank really holds a given sequence.

Far-call argument at $81CD data confirmed

bank1.inline_81CD · file 0x041DD-0x041DF · 3 bytes · PRG bank 1 · CPU $81CD-$81CF

Three bytes of far-call argument following `JSR $D76F` at bank 1 $81CA - bank number, then the target address minus one, little-endian. They select **bank 6 $8006**. The stored word is $8005 rather than $8006 because $D790 pushes these two bytes as a fake return address and lets RTS add the one back; that is not an inference, it is what the four instructions at $D799-$D7A4 do. A far call is the one reference in this ROM that no grep for an operand will ever surface, so the target is recorded here where a reader will find it.

Bank 1 identity byte data confirmed

bank1.bank_id_BFFF · file 0x0800F-0x0800F · 1 bytes · PRG bank 1 · CPU $BFFF-$BFFF

One byte at $BFFF, the last byte of PRG bank 1, holding the bank's own number. Banks 0 to 6 each carry one; bank 7 does not, because bank 7's last byte is at $FFFF and belongs to the IRQ vector. These seven bytes are the ROM half of a boot-time mapper self-test. $FF23-$FF43, reached from the reset handler, is a loop over Y = 6 down to 0: TYA / JSR $D705 selects the bank in Y, CPY $BFFF then compares Y against the byte this region holds, and BEQ $FF41 falls through to DEY only when the two agree. If they do not, LDA $FF3A,Y fetches a per-bank code, stores it at $0180, calls $DED2 and then spins forever at JMP $FF37. So the game refuses to start unless every one of the seven switchable banks can be selected and answers with its own number - which is the check a UxROM board needs, because a bus conflict on the latch fails silently and leaves the wrong bank mapped. Reading the byte at $BFFF works no matter which bank is live precisely because every bank has one at the same address and they all differ. NOT ESTABLISHED: what $DED2 does with $0180, and therefore whether the failure is displayed or merely hangs.
